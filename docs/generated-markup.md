# Разметка, написанная моделью

Как текст от Gemini проверяется до того, как станет постом.

> **Главные файлы:**
> [`use_cases/html_guard.py`](../main/domain/use_cases/html_guard.py)
> **Пользуется:** `_draft_problems`, `_validate`, `_generate_text` в
> [`use_cases/generate_material.py`](../main/domain/use_cases/generate_material.py)
> **Рядом:** [`use_cases/ai_guard.py`](../main/domain/use_cases/ai_guard.py) —
> сосед по замыслу: тот переводит провалы клиента в доменные ошибки, этот
> проверяет содержимое удачного ответа.

## Зачем модель вообще пишет HTML

Пост канала — это разметка: жирные слова, ссылка, иногда спойлер. Примеры в
[шаблоне канала](post-templates.md) хранятся как `message.html_text`, то есть
с разметкой, и модель учится манере по ним. Просить её отдавать голый текст
означало бы показывать образцы с тегами и требовать ответ без тегов —
противоречие, которое она будет нарушать через раз.

Отсюда цена: **модель регулярно ошибается в разметке**, и ошибку надо ловить.

## Почему проверяем сами, а не отдаём Telegram

Telegram — авторитетная инстанция: `parse_mode=HTML` он проверяет сам и на
битом теге отвечает `can't parse entities`. Не годится по двум причинам.

Первая: к моменту отправки **пост уже лежит в базе**, и чинить пришлось бы не
текст, а строку. Вторая: падение прилетело бы на превью, то есть после того как
админ переслал картинки, переслал файл и дождался генерации, — самый обидный
момент, чтобы узнать о лишнем `<br>`.

Поэтому проверка локальная и происходит **до** `create_draft`.

## Что разрешено

```python
b strong · i em · u ins · s strike del · code · pre
a href · span class="tg-spoiler" · tg-spoiler · tg-emoji emoji-id · blockquote [expandable]
```

Это ровно «HTML style» из Bot API. Плюс два правила: теги закрыты и вложены
корректно, а `<`, `>`, `&` вне тегов экранированы.

Список живёт в `_ALLOWED_TAGS` вместе с допустимыми атрибутами каждого тега.
Рядом — `ALLOWED_TAGS_HINT`, та же информация строкой для промпта: **подсказка
модели и правило проверки лежат в одном файле**, чтобы не разъехались.

## `HTMLParser` оказался достаточно строгим

Опасение было, что стандартный парсер слишком терпим и сырой `<` проглотит как
текст. Проверено прогоном — не проглатывает:

| Вход | Что видит парсер |
|---|---|
| `a < b` | `('data', 'a ')`, `('data', '<')`, `('data', ' b')` |
| `<блок>` | `('data', '<')`, `('data', 'блок>')` |
| `&nbsp;` | `('entity', 'nbsp')` |
| `<b><i>x</b></i>` | обе перестановки видны через стек |

Одинокий `<` приезжает **отдельным событием `data`**, а не сливается с текстом,
поэтому правило «в куске данных есть `<` — это ошибка» работает. Собственный
сканер не понадобился.

`convert_charrefs=False` обязателен: с ним `&nbsp;` превратилось бы в символ
ещё до нашей проверки, и мы бы её не увидели.

## Претензии формулируются для модели, а не для лога

`check_telegram_html` возвращает список фраз вида «`<b>` is never closed» или
«a bare '&' in the text: write it as `&amp;`». Они уходят в ремонтный промпт
дословно: модель чинит названную ошибку заметно лучше, чем переписывает пост
наугад.

Повторы схлопываются через `dict.fromkeys` — сырой `&` в каждом абзаце иначе
дал бы десяток одинаковых строк, — но порядок сохраняется: первая претензия
обычно и есть причина остальных.

## Ремонт ровно один

```
генерация → проверка → чисто? → готово
                     → есть претензии → ремонтный промпт → проверка
                                                         → чисто? → готово
                                                         → нет → срезать теги
```

Цикла нет намеренно: модель, сломавшая разметку дважды, на пятый раз её не
починит, а каждый заход стоит денег.

Запасной путь — `fallback_plain`: теги срезаются, текст остаётся. Тут есть
неочевидность, ради которой функция и написана: одного `strip_tags` мало.
Символ, приехавший корректно экранированным как `&lt;`, после срезания тегов
станет голым `<` и сломает ровно тот пост, который мы спасаем. Поэтому после
срезания текст экранируется заново через `html.escape`.

## Ссылка — часть разметки, и её тоже проверяют

Ссылка на материал не приписывается хвостом, её пишет модель внутри
`description`, оформляя так, как принято в этом канале. Значит, её отсутствие —
дефект того же рода, что незакрытый тег, и идёт через тот же ремонт.

`extract_links` вытаскивает все `href`, и проверок две:

- **нашего адреса нет** → «the link to the material is missing»;
- **есть чужой адрес** → «links to … which is a different material».

Вторая проверка важнее, чем кажется. **Примеры в шаблоне — это прошлые посты
того же канала, и в каждом уже стоит ссылка на другой материал.** Модель,
которой велено воспроизвести манеру, охотно копирует href целиком. Пост
получается внешне безупречным и ведёт не туда — молчаливая подмена, которую
никто не заметит до жалобы подписчика.

Голый адрес в тексте, без якоря, считается допустимым: Telegram линкует его сам,
и именно это остаётся после запасного пути.

## Длину считает `visible_length`

```python
len(strip_tags(text).encode("utf-16-le")) // 2
```

Две поправки разом, обе легко забыть:

- **теги в лимит не входят.** Telegram меряет то, что видит читатель, поэтому
  адрес, спрятанный в `href`, не стоит ничего. Проверено: пост из 1000 видимых
  символов плюс якорь проходит, хотя вместе с адресом было бы 1035 из 1024;
- **единица — UTF-16 code unit, а не символ.** Эмодзи вне BMP занимает две.

Это зеркало `tg_length` из презентации. Тот меряет ввод админа, этот — ответ
модели после срезания разметки. Одна арифметика, разные предметы, и слоям нельзя
импортировать друг друга — отсюда две копии.

## Грабли

- **`strip_tags` разэкранирует.** `convert_charrefs=True` внутри `_Stripper`
  превращает `&lt;` обратно в `<`. Для измерения длины это правильно, для
  публикации — нет. Всё, что прошло через `strip_tags` и едет в Telegram,
  обязано быть заново экранировано.
- **Числовые сущности запрещены.** `&#8212;` считается ошибкой: Bot API
  документирует только `&lt;`, `&gt;`, `&amp;`, `&quot;`, остальное — лотерея.
  Модели проще написать сам символ.
- **`<span>` разрешён ровно с `class="tg-spoiler"`.** Любой другой класс —
  ошибка, потому что Telegram про него не знает.
