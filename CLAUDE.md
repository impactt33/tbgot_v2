## Окружение

- **Нужен Python 3.14.0 финальный, не rc.** `uv python install 3.14` ставит rc2, на
  котором pydantic 2.13 падает при импорте любой модели:
  `TypeError: _eval_type() got an unexpected keyword argument 'prefer_fwd_module'`.
  Финальный тянуть сборкой python-build-standalone.
- **Docker-демона может не быть.** Тогда Postgres поднимается напрямую (`initdb`
  под пользователем `postgres`, порт 5430), Redis — `redis-server --port 6379`.
- Нужен `app/.env` (он в `.gitignore`) со всеми переменными из
  `core/config/settings.py`, включая `REDIS_*`. Без него падает импорт
  `core.config`: `settings = Settings()` выполняется на уровне модуля.
- Для проверок заводи отдельную базу, рабочую не трогай.

## Архитектура

Чистая архитектура, слои строго разделены:

- `main/domain/` — сущности, enum'ы, ABC репозиториев/сервисов/клиентов, доменные
  ошибки, use cases. **Не импортирует инфраструктуру.**
- `main/data/` — ORM-модели, реализации репозиториев, кэш, исходящие адаптеры.
- `main/presentation/` — входящие апдейты: хендлеры, фильтры, клавиатуры,
  состояния, CallbackData-фабрики, middleware, разбор ввода.
- `app/` — composition root: провайдеры dishka, контейнер, `run.py`, `scheduler.py`.
- `core/` — settings, логирование, `Base`, `AppError`.

Правило: **presentation = входящие апдейты, data = исходящие вызовы.**

### Конвенции

- Репозитории возвращают `None` при отсутствии, сервисы превращают это в доменную
  ошибку. «Наблюдение внизу, интерпретация наверху».
- `find_*` возвращает `None`, `get_*` кидает. Исключения документируются в докстроке.
- ORM-объекты не покидают репозиторий: везде `to_entity()`.
- Ошибки наследуют `AppError` с полями `detail` (логи) и `user_message` (чат).
  **Любой наследник обязан звать `super().__init__(detail)`** — иначе нет `.detail`
  и обработчик ошибки падает сам.
- Ветвление по `post_type` — только `match` с явным `case _`. На `else` уже трижды
  наступали: `CUSTOM` проваливался в ветку `SOURCES`.
- enum-колонки: `SAEnum(X, native_enum=False, length=16, create_constraint=True)`.
- В `Base` включён `naming_convention`.
- В ORM-моделях обязателен `from __future__ import annotations` (PEP 649).
- **mypy — источник истины**, не подсветка PyCharm.

### Решения, которые не выводятся из кода

- `RoleMiddleware` регистрируется **после** `setup_dishka` и на конкретных
  обсерверах (`dp.message`, `dp.callback_query`), а не на `dp.update` — иначе
  попадёт в другой REQUEST-контейнер, чем хендлер.
- Порядок роутеров в `run.py`: `error`, `command`, `menu`, `post`, `admin`.
  `/quit` в `command_router`, потому что он включается раньше `post_router`.
- Хендлер альбома регистрируется **раньше** обычного: aiogram пробует их по порядку
  регистрации, а у обычного нет контент-фильтра.
- Пресеты времени не несут timestamp в `callback_data`, а разрешаются заново в
  хендлере — иначе кнопка, полежавшая в чате, поставит время в прошлом.
- Фото хранятся как `file_id`: Telegram уже держит файл, скачивание не нужно.
  Оговорка — `file_id` привязан к токену бота.
- `MediaGroupCollector` обязан быть `Scope.APP`. На `REQUEST` каждая часть альбома
  попадёт в свой пустой буфер, и фича молча выродится в «пост на каждое фото».
- `PostType.MATERIAL` остаётся в энуме под будущий тип постов с материалами,
  хотя постов такого типа пока не создаётся.

## Грабли

- **Alembic и naming_convention.** В `drop_constraint`/`create_check_constraint`
  передавать **голое** имя (`"poststatus"`, `"posttype"`, `"userrole"`), иначе
  конвенция накрутит второй префикс: `ck_posts_ck_posts_poststatus`.
- **Имя CHECK идёт от имени enum-типа, а не от колонки.** Колонка `status`,
  констрейнт `ck_posts_poststatus` — на этом был баг «column post_status does not exist».
- **Смена типа колонки с дефолтом:** DROP DEFAULT → ALTER TYPE ... USING →
  SET DEFAULT → DROP TYPE. Autogenerate так не умеет, пишется руками.
- **`include_object` в `migration/env.py` прячет весь дрейф CHECK** — можно дропнуть
  все констрейнты руками, и `alembic check` промолчит.
- **`posts.id` это int4, а `channels.channel_id` — BigInteger.** Подстановка id
  канала туда, где ждут id поста, даёт `OverflowError`. Обратная пройдёт молча.
- **`callback_data` ограничен 64 БАЙТАМИ,** не символами: кириллица по 2 байта.
- **CallbackQuery можно ответить только один раз** — второй ответ не дойдёт.
  Поэтому проверки, отвечающие алертом, идут до первого `callback.answer()`.
- **Добавил поле в CallbackData — старые кнопки перестают распаковываться.**
  `unpack` кидает `TypeError`, но `.filter()` его ловит и возвращает `False`:
  падения нет, кнопка просто молчит.
- **Enum'ы в FSM data** возвращаются из Redis строками (`json.dumps`), сравнение
  через `is` ломается. Нужно приведение обратно: `ChannelAction(raw)`.
- **Лимиты Telegram считаются в UTF-16 code units,** не в символах Python: эмодзи
  вне BMP занимают две единицы. Подпись к фото 1024, сообщение 4096, альбом 10 фото.
- **Форматирование хранится отдельно от текста,** координатами в UTF-16.
  `message.html_text` собирает HTML одинаково для `text` и для `caption`.
- **Python 3.14 (PEP 649) вычисляет аннотации лениво** — ошибка в аннотации
  хендлера вылезет не при импорте, а при старте диспетчера.
- **dishka вешает `inject_router` на startup диспетчера.** В тестовой обвязке без
  `await dp.emit_startup(bot=bot)` все хендлеры с `FromDishka` падают на
  `TypeError: missing required positional arguments`.
- **PyCharm любит мусорные автоимпорты.** Профилактика:
  `grep -rnE "^from (app|pyasn1|aiohttp)\." main/ core/` должен молчать.
